# Security assumptions

Every property in [`SECURITY-REVIEW.md`](SECURITY-REVIEW.md) holds *only* if the assumptions below hold. They are listed explicitly so they can be challenged, monitored, and re-verified — an unstated assumption is an unmanaged risk. The list is deliberately short; each one is a place where correctness depends on something this codebase does not itself enforce.

| ID | Assumption | Why we depend on it | If it breaks |
|----|-----------|---------------------|--------------|
| **A-1** | **D1 is the sole authority for authorization.** Roles, permissions, agent status, and classification come from D1 on every request, resolved fresh with no caching layer. | The entire authorization model. `authorize()` reads only from the `Principal` built out of that D1 read. | Total authorization bypass. Any write path to D1 outside the admin API is equivalent to granting arbitrary permissions. |
| **A-2** | **The search index is NOT authoritative.** AI Search metadata is treated as an untrusted hint; every retrieved chunk is re-validated against the live D1 row before it is returned. | A stale, corrupted, or attacker-influenced index must not be able to release content. Proven by `tests/security/retrieval-acl.test.ts`. | Nothing — this assumption is *defensive*. It exists precisely so that compromising the index is not sufficient to leak data. |
| **A-3** | **Cloudflare Access terminates and verifies the request before the Worker sees it, and the `Cf-Access-Jwt-Assertion` header cannot be set by an external client reaching the Worker through Access.** | HTTP identity. We cryptographically verify the JWT signature/`iss`/`aud`/`exp` ourselves, so a *forged* token fails — but we assume Access is actually in front of the public hostname. | If the Worker's hostname is reachable **bypassing Access**, an attacker can still not forge a valid signature, so authentication holds. The real exposure is losing the DoS/edge protections, not identity. **Deploy check:** the Worker's public route must sit behind the Access application. |
| **A-4** | **`CF-Connecting-IP` is set by the Cloudflare edge and overwrites any client-supplied value.** | Used *only* as the pre-identity rate-limit key (SR-013). | Rate-limit evasion for unauthenticated traffic. Never an authorization impact — this header is never consulted for identity or permissions. |
| **A-5** | **R2 objects are private.** The documents bucket has no public access, no public dev URL, and no presigned-URL issuance anywhere in this codebase. | Document confidentiality. R2 keys embed classification/domain for human browsability, and are explicitly *not* a security boundary. | Direct object access bypassing all ACLs. **Deploy check:** verify public access is disabled on `knowledge-core-documents-*`. |
| **A-6** | **The AI Search instance has no public endpoint of its own** and is reachable only through this Worker's binding. |. AI Search's own MCP/public endpoint would not apply our per-agent filters. | Complete retrieval ACL bypass — an attacker queries the index directly. **Deploy check:** confirm public access is disabled on the instance. |
| **A-7** | **Retrieved knowledge is untrusted data**, and consuming agents treat it as evidence rather than instruction. | Prompt-injection defence. Xfeatures Athenaeum never calls an LLM, so it cannot itself be injected; the risk lives entirely in the consuming agent. | A compromised consuming agent, but the blast radius is still bounded by that agent's own permissions. Documented in [`AGENT-INTEGRATION.md`](AGENT-INTEGRATION.md). |
| **A-8** | **`RPC_KEY_PEPPER` is a real secret**, distinct per environment, never committed. | Makes a stolen `agents.rpc_key_hash` column useless for offline brute force. | Stolen hashes become offline-crackable. Rotating the pepper invalidates every RPC key at once (an intentional emergency lever). |
| **A-9** | **Each environment has genuinely separate D1 / R2 / Queue / AI Search resources and its own secrets.** | Environment isolation. Defence-in-depth is enforced in code too: an agent row's `environment` must match the serving Worker's (SR-011). | A staging identity could otherwise act against production data. The SR-011 check converts this from a silent failure into a hard denial. |
| **A-10** | **Only this Worker can address a `PUBLISH_WORKFLOW` instance** (workflow instances are reachable through the binding, not from outside). | The publish-approval Workflow accepts a `document-review-decision` event carrying `reviewerAgentId`. That value is set server-side in `handleReviewDecision` from the authenticated principal. | An attacker able to send workflow events directly could forge the recorded reviewer identity and force-publish. The authorization to publish still lives in the route (`documents.publish`). |
| **A-11** | **Uploaded documents are never executed or parsed by an unsafe parser.** Content is stored as opaque bytes and returned as text; no HTML/JS/PDF/macro evaluation happens anywhere. | Upload safety. This is why the allowed MIME list is narrow and PDF is deliberately excluded. | Adding a parser (especially PDF) reintroduces a whole vulnerability class and requires its own review. |
| **A-12** | **The Cloudflare platform primitives behave as documented** — D1 prepared-statement binding does not interpolate, `db.batch()` is atomic, Workers Rate Limiting is not trivially evadable, and `crypto.getRandomValues`/`crypto.subtle` are sound. | SQL-injection resistance, optimistic-concurrency atomicity, rate limiting, and all ID/secret generation. | Foundational. Verified against current docs during this review (see SR notes), but not independently testable here. |

## Deliberately *not* assumed

These are things a reader might expect us to rely on, which we specifically do not:

- **We do not assume the calling agent is honest.** Every agent — including internal Workers over a Service Binding — presents a credential and is authorized on every call. A Service Binding proves "some Worker in this account", never *which* agent.
- **We do not assume the search index is fresh, correct, or uncompromised** (A-2).
- **We do not assume classification embedded in an R2 key path is correct.** D1 is authoritative; the path is cosmetic.
- **We do not assume permission strings in D1 are well-formed.** Malformed and over-broad wildcards are rejected by the parser (SR-007), not trusted.
- **We do not assume an administrator is fully privileged.** `admin.*` permissions are scoped by classification on every resource touched (SR-002/SR-003), and an admin cannot mint an identity stronger than itself.
- **We do not assume `Content-Length` is honest** — it is required and bounds the upload *before* buffering, and the buffered result is re-checked (SR-014).

## Re-verification triggers

Re-run this review if any of the following change: the Access application or its AUD tag; R2 or AI Search public-access settings; the permission taxonomy or seed roles; the addition of any `fetch()` call (currently zero — see SR-017); the addition of a caching layer (currently none — SR-016); or the addition of any document parser.
